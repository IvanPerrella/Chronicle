# Enhanced Shipwreck renderer: implementation and validation

The [lighting plan](ENHANCED_LIGHTING_PLAN.md) records the requested direction and NVIDIA source references. This page describes the implementation and its measured limits. The visual reference is `Dark Cloud_ Gunny in the Fog.png` in the repository root. Enhanced rendering is opt-in; the original canonical PS2 image and frame-feedback path remain available.

## What runs

- The enhanced display path shades world materials in linear light into an RGBA16F target, applies Shipwreck depth/height fog and local fire scattering, bloom and tone mapping, then draws the HUD into an SDR target. The canonical image used by game feedback remains separate. Fog and the wet timber material treatment are Shipwreck-specific.
- Shipwreck 3D materials load original procedural normal and ORM (ambient occlusion, roughness, metalness) PNG maps from the executable-relative `assets/materials` directory. The nine profiles cover floor/wall timber, cloth, leather, skin, metal, stone, generic props and deliberately flat surfaces; untextured 3D props use stable world-position projection. Toan's face atlas binds Skin maps, belt/bracer atlas binds Leather, and poncho atlases bind Cloth; the mixed face/cloth atlas keeps a conservative Cloth map with a smooth-skin mask. The maps have prefiltered mip chains. The live **Surface Detail** Video setting (Off through Full) changes normal strength without a restart. The source game textures and authored UVs remain intact. The maps are reproducible with `tools/materials/generate_material_maps.py` and their provenance/license is recorded alongside them.
- Vulkan ray queries add contact AO, directional and local-fire shadows, rough reflections and a bounded diffuse bounce. Fire positions and intensity come from the game's `CFireOmni` draws and existing flicker signal. The old rectangular projected floor-light overlays are omitted in enhanced Shipwreck with RT, including when Shipwreck Lamps is toggled off.
- On supported NVIDIA Vulkan hardware with Streamline plugins, DLSS Super Resolution uses the chosen optimal internal resolution, motion vectors, jitter and depth; a production Release has observed successful `slEvaluateFeature` calls. Reflex is integrated, and the display-only SDK frame index keeps SR, FG, markers and jitter in sequence. Frame Generation requests an effective Immediate swapchain mode while preserving the saved V-Sync choice for when FG is off. The previous production Release generated additional SDK-presented frames after the Shipwreck test window gained foreground focus; capability and enabled options alone do not prove generation in a new run.
- Video settings for Atmospheric Lighting, Bloom, Ray Tracing, Shipwreck Fog, Shipwreck Lamps, Surface Detail, DLSS Quality (Off, DLAA, Quality, Balanced, Performance, Ultra Performance) and Frame Generation apply during play. Changed render targets and pipelines rebuild at a safe frame boundary, with history reset on resolution or lighting changes. The same `ConfigChange` path is used by the Options screen and the opt-in `DC_LIVE_GRAPHICS_TEST=1` integration sequence.

## Shipwreck checks

- Docker Windows release and isolated debug builds compile. A bounded Shipwreck session launched through `run.bat` exited successfully; the Streamline Vulkan device uses native Vulkan creation and SDK registration, avoiding a crash in the SDK create-device proxy.
- The standard Docker `windows-x64-release` build packages the 18 normal/ORM PNGs, manifest and license beside `darkcloud.exe`. A Shipwreck run launched from an unrelated working directory loaded 18/18 maps from that executable-relative folder and exited successfully. A separate genuinely empty Windows save completed first-run language export and entered Shipwreck after the exporter was changed to preserve non-ASCII relative filenames as UTF-8.
- A Shipwreck runtime material-slot trace loaded all 18 normal/ORM maps and confirmed face `c01d01` used Skin profile 4, leather `c01d03` used Leather profile 3, and `c01d02/04/05` used Cloth profile 2. A same-frame floor texel diagnostic also traced the pale plank fibres to the authored `d03b` atlas rather than a projected light overlay; the enhanced wood response selectively absorbs high-luminance warm texels while retaining dark grooves.
- A final single-process 1200-frame Shipwreck windowed run applied all 19 live setting transitions: HDR, RT, DLSS Performance/DLAA/Quality/Off and back to Quality, FG on/off, bloom, fog, local lights, and Surface Detail Off/Full. Target sizes followed the modes, SR evaluation succeeded, the saved FIFO mode was restored after FG off, and the process exited without a Vulkan or NGX error. The log is `.kazarov/final-live-token-qa.log`. This automated window was unfocused and the SDK counted 59 real/59 shown frames during its FG interval; the separate current-Release foreground test below establishes generated-frame operation. An offscreen run also exercised the settings using native rendering; Streamline is unavailable without a presentation surface.
- After the first enhanced Shipwreck frame, 300 consecutive actual presents used the same SDR display+HUD source; captures at frames 798, 799 and 800 had world mean RGB 48.35, 48.27 and 48.45, with consecutive world mean absolute RGB differences below 0.5 of 255. This tests the reported whole-screen flashing without filtering out canonical presents.
- A temporary diagnostic moved Toan continuously through a Shipwreck doorway to isolate fog continuity from gameplay collision. Capture frame 905 was in corridor room -1, frame 906 first entered room 5 at game tick 780, and frame 907 remained there. Across the boundary, a fixed wall region's mean luma was 40.55→40.29→40.53 and deck luma 38.40→37.77→37.55, with no visible whole-volume hue or exposure pop. The normal door collision prevented this scripted route in regular play; the diagnostic movement and logging were removed from the source after the test.
- At 1280×960 before the final material additions and the later Shipwreck culling/fog follow-up, ray profiling disabled, the same 800-tick Shipwreck replay took 9.614 s with RT versus 6.366 s without, down from 18.86 s in the earlier RT pass. An instrumented run recorded about 10.32 million rays per display frame after ray-budget and early-depth changes, versus 31.48 million earlier; instrumentation itself is not used for timing.
- Before the later Shipwreck culling/fog follow-up, the production Release 800-frame Shipwreck route at 4K output with DLSS Quality at 2560×1440, FG off and ray profiling disabled took: windowed FIFO 19.00 s RT off, 18.57 s RT on (19.48 s on repeat); Immediate 19.12 s off and 18.41 s on. Game-tick/presentation pacing dominates these wall times, so they do **not** isolate RT GPU cost or show an RT speedup. A separate native 4K offscreen pair, where DLSS is unavailable, took 6.11 s off and 9.86 s on (1.61× total wall). The matched windowed captures had floor mean luma 40.80→40.99 and wall 43.90→43.98 from RT off to on, with no broad overexposure. The accepted display capture at that stage is `.kazarov/rt-perf-final-on-windowed-4k-800.png`.
- In a current production Release Shipwreck test at 4K output, DLSS Quality input 2560×1440 and RT on, the game window (PID 59168) became foreground at monitor check 18. Streamline then reported `latest=2 status=0x0` and finished with 1,186 real frames, 1,293 SDK-presented frames and 107 generated frames (`.kazarov/fg-same-shell.log`). These totals include frames rendered before foreground activation; they do not represent a 2× rate for the whole run or physical monitor scanout. In a separate 94.90 s automated run that remained unfocused, the same Release reported 5,695 real/5,695 shown and zero generated (`.kazarov/fg-user-foreground-session-6000.log`). Before the material-map and current-pose cloth additions, an interactive RTX 4090 debug run reported 349 real and 686 SDK-presented frames over 5.75 s with FG on, versus 363 real/presented over 5.73 s with FG off; that earlier comparison is historical.
- Four 4K Shipwreck application-frame captures at moving frames 850/851, with FG off and on, had no obvious motion trail or HUD contamination. These captures cannot show SDK-generated intermediate frames.

## Shipwreck floor and room-transition follow-up

- A live Release capture in Shipwreck's porthole room showed a recognizable Toan/lantern mirror on the deck and a pale floor region at a particular camera angle (`.kazarov/live-shipwreck-user-room.png` and `.kazarov/live-user-white-floor-angle.png`). The enhanced timber shader now omits its coherent single-hit reflection ray on upward rough boards while retaining AO, diffuse bounce and broad direct lighting. Smooth and metallic surfaces retain ray reflections. In matched paused 4K DLSS Quality captures, restoring the old timber ray brought back narrow colored lamp streaks; the new path removed them (`.kazarov/rt-room2-old-wetmirror-dlss4k-paused-560.png` versus `.kazarov/rt-room2-gated-dlss4k-paused-560.png`). That controlled pose was not an exact match for the user's broad pale patch, so its individual contributing term is not conclusively isolated. The current timber prelit response also uses higher roughness and lower dielectric F0; no separate directional-light change was made in this follow-up.
- The old low Shipwreck mist plane followed Toan's most recent ground height. A natural lower-room-to-corridor traversal showed that height moving from −2 to 8 over about 17 game ticks, moving the apparent fog through the whole scene. Fog now samples a stable 20×20 collision-derived deck-height field tied to the room layout, with a fixed fallback until collision data is ready. The same traversal measured lower-room deck −2 and corridor deck 8. The depth-zero sky/background ray uses the cool far medium, while Shipwreck's cell culling accounts for cell bounds so distant room geometry arrives before the medium exposes it.
- In a regular gameplay movement test through the lower room's south doorway, captures immediately before and after the actual room switch (`.kazarov/shipwreck-room2-door-before-590.png`, `.kazarov/shipwreck-room2-door-after-592.png`, `.kazarov/shipwreck-room2-door-after-596.png`) showed continuous distant haze and geometry without the former whole-volume pop. A clean build without the temporary test pose compiled, and a 400-frame Shipwreck offscreen smoke exited successfully with fog applied through its final frame (`.kazarov/shipwreck-clean-spatial-fog-400.log`). The standard Docker Windows Release was then rebuilt and `run.bat --jump dungeon:2` relaunched with these fixes (`.kazarov/shipwreck-fixed-release-launch.log`); startup confirmed ray queries, DLSS readiness and all 18 material maps. Foreground frame generation and the user's exact broad pale-floor angle were not revalidated in that launch.

## Limits

Ray structures are built from meshes seen in the canonical/display lists, not the whole dungeon; geometry outside those lists can be absent from reflection or shadow rays. Current-pose Toan cloth is included, and a temporary final-fragment diagnostic showed its authored orange poncho texture in ray-hit pixels; the diagnostic was removed from production. Secondary hits sample texture, alpha and material maps. The diffuse bounce is deliberately bounded and has no second shadow query, so it does not equal converged GI. The latest rough upward Shipwreck boards omit the coherent reflection ray, so they do not show a sharp reflected poncho; smoother and metallic surfaces still trace it. The procedural normal maps are material-specific approximations, not original artist-authored scans. FG-generated intermediate frames cannot be inspected through the app's ordinary screenshot readback, which captures real rendered frames. Foreground SDK generation was verified in the prior production Release, while actual-display capture of generated-frame artifacts remains open.
